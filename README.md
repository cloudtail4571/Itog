## Пример паттерна "Абстрактная фабрика" (Abstract Factory) на C++

Данный проект демонстрирует реализацию порождающего паттерна проектирования **Abstract Factory**, который позволяет создавать семейства связанных объектов, не привязываясь к конкретным классам продуктов.

##  Анализ кода

Основная цель реализации — обеспечить **совместимость** элементов графического интерфейса (UI). Паттерн гарантирует, что все созданные компоненты (кнопки, скроллбары, чекбоксы) будут принадлежать одной и той же операционной системе.

### Основные компоненты:
*   **Абстрактные продукты (`Button`, `ScrollBar`, `CheckBox`)**: Интерфейсы, общие для всех вариаций элементов.
*   **Конкретные продукты**: Реализации под конкретные ОС (например, `WinButton` или `LinuxScrollBar`).
*   **Абстрактная фабрика (`UIFactory`)**: Общий интерфейс для создания всех типов продуктов.
*   **Конкретные фабрики (`WinFactory`, `LinuxFactory`)**: Классы, которые инкапсулируют логику создания объектов конкретной платформы.

## Преимущества подхода

1.  **Гарантия совместимости**: Вы никогда не получите "смешанный" интерфейс (например, Windows-кнопку в Linux-окружении).
2.  **Принцип единственной ответственности**: Весь код создания продуктов сосредоточен в одном месте (в конкретной фабрике).
3.  **Принцип открытости/закрытости**: Можно добавлять новые семейства продуктов (например, `MacOSFactory`), не изменяя существующий клиентский код.
4.  **Упрощенная настройка**: Замена всего интерфейса происходит путем изменения одной строки кода при инициализации фабрики.
