# Реализация паттерна "Адаптер" на C++

Этот проект демонстрирует работу структурного паттерна проектирования **Adapter (Адаптер)**. Программа имитирует подключение устаревшего оборудования (LPT-принтеры и сканеры) к современному USB-интерфейсу.

## Анализ: Почему Адаптер лучше изменения старого класса?

При работе с Legacy-кодом (устаревшим кодом) создание адаптера предпочтительнее прямого редактирования по трем причинам:

1.  **Принцип открытости/закрытости (OCP):** Мы расширяем систему новым функционалом, не рискуя сломать старый, протестированный годами код.
2.  **Принцип единственной ответственности (SRP):** Старый класс продолжает отвечать за логику работы с железом, в то время как адаптер берет на себя только логику преобразования интерфейсов.
3.  **Отсутствие исходников:** Часто старый код поставляется в виде закрытых библиотек (.dll, .so), и адаптер — единственный способ интегрировать их в новый проект.

## Структура решения

### 1. Интерфейс (Target)
`USBDevice` — современный абстрактный интерфейс, который ожидает клиентский код.

### 2. Адаптируемые классы (Adaptee)
*   `OldLPTPrinter`: Старый принтер с методом `printLPT`.
*   `OldLPTScanner`: Старый сканер с методом `scanLPT`.

### 3. Типы реализации адаптера в коде
*   **Адаптер объекта (Object Adapter):** Использует композицию (хранит указатель на объект). Примеры: `PrinterAdapter`, `ScannerAdapter`.
*   **Адаптер класса (Class Adapter):** Использует множественное наследование. Пример: `PrinterClassAdapter`.
