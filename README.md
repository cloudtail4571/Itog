# Vending Machine (Pattern State)

Простая реализация торгового автомата на языке C++, демонстрирующая работу поведенческого паттерна проектирования **State (Состояние)**.

## Описание проекта
Программа имитирует работу автомата по продаже напитков. Главная особенность — использование объектов для управления состояниями вместо громоздких конструкций `if-else`. Это делает код гибким, расширяемым и легким для чтения.

### Включенные возможности:
*   **Инкапсуляция логики**: Каждое состояние (есть монета, нет монеты, выдача) живет в своем классе.
*   **Механика "Счастливая покупка"**: Каждый 3-й покупатель получает дополнительный напиток бесплатно (**WinnerState**).
*   **Контроль запасов**: Автомат автоматически блокируется, когда напитки заканчиваются.

---

## Архитектура

### Основные классы:
1.  **`VendingMachine` (Контекст)**: Хранит текущее состояние, количество товара и управляет их сменой.
2.  **`State` (Интерфейс)**: Определяет набор методов, которые должны реализовать все состояния (`insertCoin`, `dispense`, `ejectCoin`).
3.  **Конкретные состояния**:
    *   `NoCoinState`: Ожидание оплаты.
    *   `HasCoinState`: Монета принята, проверка условий выдачи.
    *   `WinnerState`: Специальный режим выдачи бонусного напитка.
    *   `SoldOutState`: Режим "Товар закончился".

### Схема переходов:
- **Нет монет** + `insertCoin()` ➔ **Есть монета**
- **Есть монета** + `dispense()` ➔ **Нет монет** (или **Победитель**)
- **Запас = 0** ➔ **Товар закончился**

---

## Почему это лучше, чем `if-else`?

В коде реализованы три ключевых преимущества паттерна:
1.  **Принцип открытости/закрытости (OCP)**: Мы добавили `WinnerState`, практически не меняя код самого автомата.
2.  **Отсутствие "спагетти-кода"**: Методы не превращаются в каскады проверок типа `if (inventory > 0 && hasCoin)`.
3.  **Локализация правок**: Если нужно изменить поведение при возврате монеты, правки вносятся только в один класс.
